# Praxis Engine: How It Works & the “Trend” Algorithm

This doc explains how the engine selects outfits and how “trends” are used. **Important:** the system does **not** pull trends from the web; “trends” are an **AI-generated text description** used to style images.

---

## 1. End-to-end flow (Quick / Style a Moment)

```
User flow (occasion, context, preferences)
    → POST /api/generate-outfits (Decision Engine)
    → Intent (rule-based or AI) → Map to 3 outfit IDs (SAFEST, SHARPER, RELAXED)
    → POST /api/generate-trend-outfits (flowData + those 3 outfit concepts)
    → Trend text (Gemini) → Per-outfit image (Gemini Image)
    → UI shows 3 outfits with generated images + reasoning
```

If the trend API fails (e.g. missing API key), the app **falls back** to the same 3 outfits with **static library images** (`outfitLibrary.ts` + `image_url`).

---

## 2. Decision Engine (outfit selection algorithm)

Outfit suggestions come from a **curated static library**, not from live web or trend feeds.

### 2.1 Input: FlowData → Intent

- **Source:** `flowData` (occasion, context, preferences) from the Style a Moment form.
- **Intent builder:** `src/lib/decisionEngine/intentBuilder.ts`
  - Maps occasion → `formality` (e.g. WEDDING → high, DATE → medium).
  - Maps priority → `vibe` (SHARP → sharp, COMFORT → comfort, SIMPLE → relaxed).
  - Maps when → `temperature` (DAY/NIGHT → mild).
  - Derives `risk` from priority.
- **Optional:** If `GEMINI_API_KEY` is set, `classifyIntentWithAI()` can override intent with AI (e.g. `psychological_goal`, `mood`); otherwise rule-based intent is used.

### 2.2 Mapping: Intent → 3 outfit IDs

- **Source:** `src/lib/decisionEngine/mappingEngine.ts`
- **Steps:**
  1. Load **valid outfits** from `outfitLibrary.ts` (curated list with `id`, `occasion`, `tier`, etc.).
  2. Filter by **occasion** (e.g. DATE, WORK) so only matching library entries are considered.
  3. For each **tier** (SAFEST, SHARPER, RELAXED):
     - Take all library outfits that have that tier.
     - Attach **metadata** from `outfitMetadata.ts` (formality, silhouette, vibe, fabric_weight, etc.).
     - **Score** each candidate with a fixed formula (see below).
     - **Pick the highest-scoring** outfit in that tier.
  4. Return exactly **3 mapping results** (one per tier), each with `outfitId`, `tier`, `abstract`, `score_breakdown`, `retailer_ids`.

### 2.3 Scoring formula (Chain-of-Style)

- **Source:** `mappingEngine.ts` — `computeScoreBreakdown()` + `compositeScore()`.
- **Weights:**
  - **body_harmony** — 25%
  - **color_harmony** — 20%
  - **event_appropriateness** — 20%
  - **psychological_projection** — 15%
  - **weather_compatibility** — 10%
  - **user_preference_match** — 10%

- **How the breakdown is computed (conceptually):**
  - **event_appropriateness:** formality match (intent vs abstract); fallbacks for medium intent.
  - **user_preference_match:** vibe match (intent vs abstract).
  - **psychological_projection:** higher if AI set `psychological_goal`.
  - **color_harmony / body_harmony / weather_compatibility:** fixed or simple rules (e.g. temperature vs fabric_weight).

- **Composite score** = weighted sum of the breakdown (0–1) × 100. The **top scorer per tier** is chosen.

### 2.4 Reasoning and response

- For each of the 3 chosen outfits, **reasoning** (summary, silhouette, color_logic, context_logic) is generated:
  - With Gemini: `generateExplanationWithAI()`.
  - Without: `generateReasoning()` (rule-based from intent + abstract).
- The API returns **intent**, **outfits** (with reasoning, confidence, score_breakdown, retailer_ids), and **thinkingSteps**.

**Summary:** The “algorithm” is **filter by occasion → score by metadata vs intent (weighted formula) → pick best per tier**. No web crawl, no live trend APIs.

## 3. “Trend” path: no online trend pull

“Trends” in this codebase are **not** fetched from the internet. They are:

1. A **short text description** of “current trends that fit this context,” generated by **Gemini (text)** from flowData.
2. That description is then injected into **image prompts** for **Gemini (image)** to render each of the 3 outfit concepts in a “trendy” way.

### 3.1 API: `POST /api/generate-trend-outfits`

- **Input:** `flowData` + `outfits` (array of concepts: id, title, label, items, reason).
- **Source:** `api/generate-trend-outfits.ts`.

### 3.2 Step 1: “Trend research” (text only)

- **Function:** `researchTrends(flowData, apiKey)`.
- **Model:** `gemini-2.5-flash` (generateContent).
- **Prompt:** Fixed template asking for “current trends” that fit the **occasion, location, time, setting, budget, priority** in 2–4 short, visual sentences (silhouettes, colors, fabrics, vibe).
- **Output:** A single string `trendSummary` — no APIs, no scraping, no RSS, no search.

### 3.3 Step 2: Image generation per outfit

- For each outfit concept:
  - **Prompt:** Professional fashion photo of a male model; outfit description (title, items.top/bottom/shoes); style label; occasion/time; **“Apply these current trends: {trendSummary}”**; photorealistic, editorial.
  - **Model:** `gemini-2.5-flash-image` (or `GEMINI_IMAGE_MODEL` env) — generateContent with image output.
  - **Output:** One image per outfit (base64 data URL).
- Response: `{ success, trendSummary, outfits: [{ id, imageUrl }] }`.

So the **algo** for “trend” is: **(1) Gemini text: “describe trends for this context” → (2) Gemini image: “draw this outfit + these trends”**. No external trend data.

## 4. Where each piece lives

| Piece | Role |
|-------|------|
| `flowDataToIntent` | FlowData → Intent (rules; optional AI override). |
| `classifyIntentWithAI` | Optional richer intent (e.g. psychological_goal). |
| `mapIntentToOutfitIds` | Intent + library + metadata → 3 outfit IDs + score_breakdown. |
| `getValidOutfits` / `outfitLibrary.ts` | Curated outfit list (occasion, tier, items, image_url). |
| `getOutfitMetadata` / `outfitMetadata.ts` | Formality, vibe, silhouette, etc. per outfit. |
| `computeScoreBreakdown` / `compositeScore` | Scoring formula for mapping. |
| `generate-trend-outfits` | Trend text (Gemini) → trend-styled images (Gemini). |
| `getOutfitsWithTrend` (client) | Calls generate-outfits then generate-trend-outfits; merges images into engine result. |

---

## 5. Summary

- **Engine:** FlowData → Intent → **score library by metadata vs intent** (weighted body/color/event/psychological/weather/preference) → **best per tier** (SAFEST, SHARPER, RELAXED) → reasoning (rule-based or AI). All outfit options come from a **static library**.
- **Trends:** **No** online trend pull. “Trends” = **Gemini-generated trend description** from flowData, then **Gemini-generated images** that apply that description to the 3 chosen outfit concepts. To add real trend data (e.g. scraped or API), you’d add a separate step (e.g. fetch trends, then feed that into the trend prompt or a new pipeline) and keep the rest of the engine as-is.
